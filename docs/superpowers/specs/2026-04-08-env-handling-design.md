# Design: 环境变量文件处理（处理 `.env`）

- **Date:** 2026-04-08
- **Topic:** `.env` 文件处理与仓库跟踪状态确认
- **Status:** Approved for this step

## 1. 背景

walkthrough 将“处理 `.env`”列为第一个 P0 安全项，目标是避免将真实敏感配置继续保留在版本库中，并确保仓库只保留可安全共享的示例配置。

经检查，当前仓库已经满足这一目标：

- `.gitignore` 已忽略 `.env` 与 `.env.*`，并显式保留 `.env.example`
- `.env` 当前未被 git 跟踪
- `.env.example` 已存在，内容为示例配置

因此，这一步不需要修改业务代码，也不需要调整当前忽略规则。

## 2. 目标

确认并保留当前环境变量文件策略：

1. 本地真实配置使用未跟踪的 `.env`
2. 仓库中只提交 `.env.example` 作为模板
3. 不对现有业务逻辑、构建流程或运行时行为做改动

## 3. 方案选项

### 方案 A（采用）

维持现状，只确认仓库状态已经符合要求，不做额外代码修改。

**优点：**
- 最小变更
- 无行为风险
- 与当前仓库状态一致

**缺点：**
- 不额外增强文档或启动时校验

### 方案 B

在方案 A 基础上补充 README 或其他文档，说明 `.env` / `.env.example` 的使用方式。

**优点：**
- 对协作者更友好

**缺点：**
- 超出本步骤的最小范围
- 会产生文档变更，但不改变实际安全状态

### 方案 C

在方案 B 基础上，增加启动期对示例值或弱默认值的校验。

**优点：**
- 可进一步避免误用示例配置

**缺点：**
- 引入运行时行为变化
- 超出当前步骤范围

## 4. 采用设计

本步骤采用 **方案 A**：

- 保持当前 `.gitignore` 规则不变
- 保持 `.env.example` 作为唯一受版本控制的环境变量模板文件
- 不创建、不提交、不修改本地 `.env`
- 将该步骤视为“状态确认完成”，而不是“新增代码改动”

## 5. 验证方式

本步骤的完成条件：

- `.gitignore` 中包含对 `.env` 的忽略规则
- `git ls-files -- .env` 无输出，表示 `.env` 未被跟踪
- `.env.example` 存在并保留示例值

## 6. 非目标

以下内容不包含在本步骤中：

- 轮换已经泄露的外部凭据
- 修改 README
- 增加运行时环境校验
- 修改认证、SMTP、数据库等相关业务逻辑

## 7. 测试与风险

### 测试

本步骤无需单元测试或 e2e 测试，因为不涉及代码行为变更。

### 风险

风险极低。本步骤不改变运行逻辑，仅确认仓库状态与环境文件策略。
